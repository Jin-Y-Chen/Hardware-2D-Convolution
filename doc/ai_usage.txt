    Q: Verilog global function structure and how does that differ from module instantiation

    R: A function is called (y = f(x)): combinational, one return, inlined. Closest to global is a package function (import pkg::*;). A module is instantiated and wired; it always exists and can have clocks/state. Do not call a module or instantiate a function.

    ---------------------------------------------------
    Q: If you want to reference a module inside a function, where do I instantiate the module?

    R: You cannot instantiate a module inside a function. Instantiate it in the parent module body (same level as always_ff). Wire its ports to signals; the function can only use those signals, not the instance.

    ---------------------------------------------------
    Q: Is this legal parameterization: memory #(.WIDTH(WIDTH), .SIZE(R * C)) X_matrix (); 

    R: The #(.WIDTH(WIDTH), .SIZE(R * C)) part is legal. A parent parameter and an expression like R * C are valid overrides

    Q: in a FSM setup where we use enum, the first state value is also the default value that the design default to in the hardware?

    R: First enum label is encoding 0 unless you assign a value. That is not an automatic reset. FFs do not start in idle unless you write state <= idle on reset (or initialize the declaration). Power-up 0 matching idle is coincidence.

    ---------------------------------------------------
    Q: Then do I assign state = Idle to make the starting state in the hardware.

    R: Yes, on reset in always_ff: if (reset) state <= idle. Use <= and the enum name idle (case sensitive). state = idle is blocking / not the hardware reset. You already have this.

    ---------------------------------------------------
    Q: Error: near "TUSER_Q": Syntax error. Unexpected range following an IDENTIFIER.

    R: Logic (capital L) is not a type. The tool treats it as a name, then [6:0] is an illegal range after that name. Use logic [6:0] TUSER_Q;

    Q: what are some traversal idea for a fixed window to stride through an undetermine X-matrix dimension. The next windows must fit within the x-matrix
    after the window had shift by strided amount, thus some columns or rows is allow to be skip as the windows traverse through the x-matrix in row major order.
    In other word, moving the window require seting a counter value (counter will increments each element in the window) to the corresponding address of input_mems
    that stores the value. Striding the next window need to account if it will fit in the same column or have to skip to the next row and striding to the new row
    will be multiple of the column size of the x-matrix by the stride. 
    

    A: The address of X[row][col] is row * C + col, where C is the matrix width. It is not row_ptr * column_ptr. 

    Keep the address of the window's top-left and scan the K by K window from there. The next column is addr + 1. 
    
    The end of a window row is addr + (C - K + 1), which jumps from column c0+K-1 to the next row at column c0. W_read_addr is a separate counter that adds 1 for each of those K*K steps, then returns to 0.

    The next window fits in this row when c0 + S <= C - K. Then the new top-left is origin + S. C - K is a constant. If it does not fit, the next row fits when r0 + S <= R - K. The new top-left is the current row base plus S*C, and the column origin returns to 0.


    Q: there is the problem of not using any multiplication

            if (next_window + S > C - K)            // C is not adjust per row, C need to be a mulitple of Row
                next_window <= next_window + (C - K)// next row but does not stride to the apporiate row or current row + (c-1)*S + 1
            else 
                next_window <= next_window + S;

    how to compare for any row that the next_window must move to the next row ?

    A: Keep row_base, the address of column 0 on the current window row. It starts at 0. The test on every row is 
    next_window + S > row_base + (C - K). 
    
    row_base + (C - K) is the last legal column of this row, so the limit moves with the row. 

    Q: Without multiplication of S how do get the next row based on the Stride value at run time

    A: Add C, S times. C is the constant row length, so each add moves one image row down, and S adds move S rows down. That sum is S*C with no multiply.

    row_base starts at 0. When the next window does not fit in this row, add C to row_base once per clock and count until the count equals S. next_window then becomes that new row_base, which is column 0 of the row S image rows below. Adding C - K only steps inside the current window. It does not stride to the next row.

    Q: here is the example for calculating next window with always comb:

    alwasy_ff(posedge clk) begin
        if (reset) 
            next_window <= S;
        else if (state == next_window && new_window = 1); since at posedge clk new_window = 0;
            next_window <= next_window + S;             


    always_comb begin
        new_window = 0;
        case(state)
        ...
        next_window : begin
            new_window = 1;             // after posedge clk new_window = 1; 
            X_read_addr = next_window;  // will it be S or 2S after and rest then a posedge clk 
        end 
        ...
        endcase;
    end;

    lets say next_window <= S on reset and does not change until state == next_window, will X_read_addr = S or 2S. 

    A: X_read_addr is S on the clock that enters state next_window. always_comb reads the register before the 
    nonblocking update, so next_window + S is scheduled as 2S and is visible only on the following clock. 
    new_window is also 0 at that edge, because it still follows the previous state. It becomes 1 after state updates.

    The semicolon after the else if makes next_window <= next_window + S run on every clock that is not reset, 
    and new_window = 1 assigns instead of compares. With that semicolon, next_window does not stay at S until 
    the state matches.

    Q: How do you do the floor operation in localparam in verliog?

    A: Integer division in a localparam already rounds down to the nearest integer when both sides are non-negative. 
    (R - K) / S drops the fraction, so localparam ROUT = (R - K) / S + 1 is the floor 

    Q: This is the same complexity as if I just do S * C?

    always_comb begin 
        i = 0;
        stride_column_amt = 0;
        while (i < S_BITS) 
            stride_column_amt += (S[i:i]) C << i ? 0
    end;

    A: Yes. Each bit of S adds a shifted copy of C: bit 0 adds C, bit 1 adds C<<1, bit 2 adds C<<2. That sum is S*C. 
    A combinational while does not run S times at runtime. Synthesis unrolls it into S_BITS adders in one cycle, the 
    same circuit as based_row + S*C.

    Adding C once per clock, S times, is the smaller circuit. It uses one adder and takes S cycles.

    Q: Add C per cycle wouldn't work if if S >  K^2 * (C - K)/S, taking more cycle to add the next row. Whats a better alternative?

    A: Use one cycle of S*C. C is constant, so S*C is a constant multiply, and next_window <= based_row + S*C is ready on the clock that leaves the row.

    Adding C once per clock needs S cycles, and those cycles have to fit inside the current row. A row is about Cout*K^2 cycles, with Cout = (C - K)/S + 1.
     The product K^2 * (C - K)/S drops that extra window, so the real limit is S > Cout*K^2. Large S makes Cout smaller, which is when the S adds no longer 
     hide behind the row. S*C does not depend on that limit.
