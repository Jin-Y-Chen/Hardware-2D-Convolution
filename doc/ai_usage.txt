    Q: why is the critical path consistently from bit [0] to bit [47] of out\accum\reg in reg2

    R: In an adder, a change on the LSB can affect every higher sum bit. The MSB waits the longest, so STA reports [0] → [47].

Date: 10/10
    ---------------------------------------------------
    Q: Verilog global function structure and how does that differ from module instantiation

    R: A function is called (y = f(x)): combinational, one return, inlined. Closest to global is a package function (import pkg::*;). A module is instantiated and wired; it always exists and can have clocks/state. Do not call a module or instantiate a function.

    ---------------------------------------------------
    Q: If you want to reference a module inside a function, where do I instantiate the module?

    R: You cannot instantiate a module inside a function. Instantiate it in the parent module body (same level as always_ff). Wire its ports to signals; the function can only use those signals, not the instance.

    ---------------------------------------------------
    Q: Is this legal parameterization: memory #(.WIDTH(WIDTH), .SIZE(R * C)) X_matrix (); 

    R: The #(.WIDTH(WIDTH), .SIZE(R * C)) part is legal. A parent parameter and an expression like R * C are valid overrides

    ---------------------------------------------------
    Q: in a FSM setup where we use enum, the first state value is also the default value that the design default to in the hardware?

    R: First enum label is encoding 0 unless you assign a value. That is not an automatic reset. FFs do not start in idle unless you write state <= idle on reset (or initialize the declaration). Power-up 0 matching idle is coincidence.

    ---------------------------------------------------
    Q: Then do I assign state = Idle to make the starting state in the hardware.

    R: Yes, on reset in always_ff: if (reset) state <= idle. Use <= and the enum name idle (case sensitive). state = idle is blocking / not the hardware reset. You already have this.

    ---------------------------------------------------
    Q: Error: near "TUSER_Q": Syntax error. Unexpected range following an IDENTIFIER.

    R: Logic (capital L) is not a type. The tool treats it as a name, then [6:0] is an illegal range after that name. Use logic [6:0] TUSER_Q;

Date: 10/11

    Q: What is the differences between latency and throughput?

    R: Latency is the time for one input to finish (L = N_cyc t). Throughput is how many results finish per second (TP = 1/t after the pipe is full). Pipe can have higher TP and worse latency.

    Q: can you do positive edge on a combinational block?

    R: No. always_comb cannot use posedeg. A clock edge is sequential, so it belongs in always_ff 

Date: 10/12

    Q: When should AXIS_TREADY be low?

    R: Low only when a transfer must not happen. The spec keeps it high through every W word, the one B word, and every X word, then low after the last X until compute_finished. That is the input_loaded phase, with inputs_loaded=1. It is not low between B and X. In the RTL it also drops in input_W when mem_addr hits the last W address, and for one cycle in input_B after B is accepted.
